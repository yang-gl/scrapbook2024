Enhancing LLMs with Function Calling: A Practical Guide

Olujare Dada
9 min read
·
Nov 16, 2024

When working with Large Language Models (LLMs), you often need them to process input data and generate outputs like extracted information, predefined responses, or simple Boolean values. These outputs typically dictate the next steps in your workflow. For example, you might want an LLM to determine if a block of text is spam, returning True or False. Based on this output, you could execute a function to move the message to the spam folder or keep it in the inbox.

This setup, while functional, can limit the LLM to a binary role. Adding more complex capabilities often requires extensive and unwieldy prompt engineering. A better approach is to let the LLM interact with your custom code directly, using its output to trigger specific functions. For instance, instead of crafting prompts to handle spam detection and action, the LLM could invoke predefined functions to handle tasks like moving emails between folders. This approach keeps prompts simple and makes LLMs more versatile.

Introducing Function Calling

Function calling allows an LLM to invoke user-defined functions, enabling it to interact seamlessly with external systems. This feature greatly enhances the LLM’s utility. For example:

  • Mathematical Computations: An LLM can use a calculator API via a function call to handle complex calculations.
  • Customer Support Chatbots: While addressing FAQs, the LLM can call backend functions for tasks like retrieving order statuses or processing return requests.

By bridging the gap between LLMs and external tools, function calling transforms LLMs from isolated text processors into powerful, integrated systems. Furthermore, the flexibility of the LLM remains intact — it can still seamlessly handle questions or requests unrelated to the provided tools.

My Use Case: Website Traffic Analysis with Function Calling

In this article, I’ll demonstrate a practical use case of function calling: analyzing website traffic data stored in a container service like an S3 bucket or Azure Data Lake. My goal is to extract two key statistics:

  1. Summarized General Statistics: Metrics like average traffic spikes, outliers, and bot edits exceeding a threshold.
  2. Aggregated User Statistics: Data grouped by users and their respective namespaces.

We’ll define two functions to handle these tasks, and use OpenAI’s LLM to invoke them via function calling. This setup simplifies our workflow while leveraging the LLM for broader tasks beyond just summarization.

def summarize_general_stats(folder_path: str, file_name: str) -> Dict:
    """
    Summarizes general statistics (such as count, mean, std, min, max, etc.) 
    from a Parquet file stored in Azure Data Lake Storage (ADLS).
    """

    directory_client = container_client.get_directory_client(folder_path)
    directory_client.create_directory()
    file_client = directory_client.get_file_client(file_name)
    try:
        downloaded_data = file_client.download_file()
    except ResourceNotFoundError:
        print(f"File {file_name} not found in {folder_path} on ADLS.")
        return "No data to summarize"
    
    parquet_data = downloaded_data.readall()
    adls_df = pd.read_parquet(io.BytesIO(parquet_data))
    general_stats = adls_df.describe()
    return general_stats.to_dict(orient="list")

2. Generate Aggregated Statistics

This function groups the data by user and namespace and optionally truncates based on word count.

def generate_aggregated_stats(folder_path: str, 
                              file_name: str, 
                              word_cutoff: int = 2600
                              ) -> Union[Dict[str, list], str]:
    """
    Generates aggregated statistics by grouping data based on 'user' and 'namespace', summing up numeric columns,
    and truncating the 'parsedcomment' column if the total word count exceeds the specified word cutoff.
    """

    directory_client = container_client.get_directory_client(folder_path)
    directory_client.create_directory()
    file_client = directory_client.get_file_client(file_name)
    try:
        downloaded_data = file_client.download_file()
    except ResourceNotFoundError:
        print(f"File {file_name} not found in {folder_path} on ADLS.")
        return "No data to summarize"
    
    parquet_data = downloaded_data.readall()
    adls_df = pd.read_parquet(io.BytesIO(parquet_data))
    aggregated_df = adls_df.drop(["timestamp", "ingestion_date", "id"], axis=1).groupby(["user", "namespace"]).sum()
    aggregated_df = aggregated_df.reset_index()

    for idx, row in aggregated_df.iterrows():
        total_words = sum(len(str(row[col]).split()) for col in ["title", "user", "title_url", "parsedcomment"])
        if total_words > word_cutoff:
            truncated_df = aggregated_df.head(idx) if idx > 1 else aggregated_df.head(1)
            truncated_df["parsedcomment"] = truncated_df["parsedcomment"].astype(str).str[:50]
            return truncated_df.to_dict(orient="list")
    
    return aggregated_df.to_dict(orient="list")

Handling JSON Serialization

def prepare_data_for_json(data):
    """
    Prepares data for JSON serialization by:
    - Converting Pandas Timestamp objects to ISO 8601 string format.
    - Replacing NaN values (Not a Number) with None for JSON compatibility.
    """

    prepared_data = {}
    for key, values in data.items():
        # Convert Timestamp objects to ISO strings and replace NaN with None
        prepared_data[key] = [
            value.isoformat() if isinstance(value, pd.Timestamp) else (None if pd.isna(value) else value)
            for value in values
        ]
    return prepared_data

The prepare_data_for_json function prepares function outputs for JSON serialization, addressing:

  • Timestamps: Converted into ISO strings for readability.
  • NaN Values: Replaced with None for compatibility with JSON standards.

Conversing with the LLM

def run_conversation(content: str)-> str:
    """
    Runs a conversation with the AI model, processes tool calls, and returns the final model-generated message.
    
    This function sends the user's message to the AI model, processes any tool calls (e.g., calling functions like
    `summarize_general_stats` or `generate_aggregated_stats`), and sends the results back to the model for further 
    processing. The function finally returns the content of the AI's second response.

    Args:
    """

    # Step 1: Initialize the conversation with the user's content
    messages = [{"role": "user", "content": content}]
    
    # Step 2: Send the initial request to the AI model
    response = client.chat.completions.create(model = "gpt-4o", 
                                              messages = messages, 
                                              tools = tools_definition, 
                                              tool_choice= "auto"
                                              )
    
    # Step 3: Process the AI's response and check for any tool calls
    response_message = response.choices[0].message
    tool_calls = response_message.tool_calls
    
    if tool_calls:
        
        # If there are tool calls, append the response message to the messages list
        messages.append(response_message)
        
        # Define available functions that the model can call
        available_functions = {"summarize_general_stats": summarize_general_stats,
                               "generate_aggregated_stats": generate_aggregated_stats
                               }
        
        # Step 4: Iterate over the tool calls, process them, and call the corresponding functions
        for tool_call in tool_calls:
            print(f"Function: {tool_call.function.name}")
            print(f"Params: {tool_call.function.arguments}")
            
            function_name = tool_call.function.name
            function_to_call = available_functions[function_name]

            # Parse the tool's arguments
            function_args = json.loads(tool_call.function.arguments)

            # Call the appropriate function and prepare the response data
            function_response = function_to_call(
                folder_path = function_args.get("folder_path"),
                file_name = function_args.get("file_name")
                )
            
            # Prepare the function's response data for JSON serialization
            function_response = prepare_data_for_json(function_response)
            
            # Add the function response to the messages list
            messages.append(
                {
                    "tool_call_id": tool_call.id,
                    "role": "tool",
                    "name": function_name,
                    "content": json.dumps(function_response)
                    }
                )
    
    # Step 5: Send the updated conversation to the model for further processing
    second_response = client.chat.completions.create(
        model = "gpt-4o",
        messages = messages,
        )
    
    # Return the content of the AI's second response
    return second_response.choices[0].message.content

The run_conversation function handles user queries while dynamically invoking registered tools:

  1. Initiating Conversation: A message from the user initializes the interaction.
  2. Requesting GPT-4 Output: The LLM processes the message, potentially suggesting tool calls.
  3. Tool Execution: The LLM’s suggested tools are matched to corresponding Python functions. Tools are executed with parsed arguments (e.g., folder path and file name). Outputs are processed for JSON compatibility and appended back into the conversation.
  4. Returning Final Response: Once tools have been executed, the LLM combines their results into a coherent reply.

Insights into Tool Execution

  • Dynamic Tool Calls: The LLM automatically determines when to use tools based on user input.
  • Tool Mapping: A dictionary maps tool names to their Python counterparts for seamless execution.
  • Conversation Persistence: Both the tool calls and their outputs are preserved in the conversation history, enabling contextual awareness.

Enhanced Question Handling

def ask_question(question: str):
    """
    Sends a question to the assistant by formatting it into a prompt template, 
    runs the conversation, and returns the assistant's response.

    This function formats a question using a prompt template, appends the question 
    to the content, and then runs the conversation by calling `run_conversation`. 
    The assistant's response is returned as a string.
    """
    
    content = PromptTemplate.content.value.format(folder = LLM_LOG_FOLDER, file = llm_logfile)
    content += question

    assistant_response = run_conversation(content)
    
    return assistant_response

The ask_question function integrates the prompt template with a user-defined question, ensuring the query is both contextual and structured. It then invokes run_conversation to process the question and fetch a response.

Conclusion

This implementation showcases the seamless integration of OpenAI’s GPT-4 with custom Python functions to create a highly interactive and intelligent system. By enabling the model to call functions dynamically, the system bridges the gap between conversational AI and data-driven decision-making.

Such a framework can be applied across domains, from monitoring automated workflows to querying complex datasets. The modular design ensures flexibility, allowing new tools to be incorporated effortlessly as requirements evolve.

Whether deployed as a Telegram bot, a web interface, or any other platform, this approach exemplifies how LLMs can extend their utility beyond conversation to become powerful data-interaction tools.
