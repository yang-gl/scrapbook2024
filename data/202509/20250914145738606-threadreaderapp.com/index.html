重温一下Anthropic 发布了的指南：“如何构建有效的 AI Agents”

2025 年将是 AI Agents 之年 🤖
以下是所有内容：🧵

翻译自MatthewBerman的推文
简单 > 复杂

在构建大语言模型（LLM）代理时，最成功的实现都使用基本的、可组合的模式。

我的看法：Agentic 框架非常适合在构建代理模式时无需重新发明轮子。
🔄 两种主要类型的 Agentic 系统：

• 工作流：预定义的路径
• 代理：动态的、自主的系统

🛠️ 从简单开始！仅在需要时增加复杂性。许多应用程序只需单次 LLM 调用 + 检索即可正常工作。
🔍 关键工作流模式：

• 提示链
• 路由
• 并行化
• 协调器-工作器
• 评估器-优化器

下文将进行解释 👇
💡 提示链

顺序 LLM 调用，其中一个调用的输出作为另一个调用的输入 - 就像先编写内容然后翻译一样

最适合具有明确子任务的任务，例如：

• 编写 + 翻译内容
• 创建大纲，然后创建完整文档
🔀 路由

初始 LLM 确定哪个专用模型处理任务，非常适合按复杂性对查询进行排序

在处理不同类型的输入时表现出色：

• 客户服务查询
• 基于难度的任务分配
⚡️ 并行化

将任务分解为并行的子任务或使用多个 LLM 对答案进行投票

这有两种主要形式：

• 分段：分解为子任务
• 投票：多次尝试以获得置信度
🎯 协调器-工作器

可以将其视为一个中央指挥，领导着一个由专门的 AI 工作器组成的管弦乐队。

协调器：
• 动态地分解复杂任务
• 委派给工作器 LLM
• 将它们的结果合成为一个连贯的输出

非常适合：需要跨多个文件进行更改的复杂编码项目
🎭 评估器-优化器

这种模式创建了一个反馈循环，其中：

• 一个 LLM 生成响应
• 另一个 LLM 评估并提供反馈
• 重复该过程，直到达到质量目标

非常适合：需要多轮改进的文学翻译和复杂搜索任务
🎯 Agents 最适合：

• 开放式问题
• 需要灵活性的任务
• 需要自主决策的情况

⚠️ 请记住：Agent 用更高的成本和潜在的错误换取了自主性。始终在沙盒环境中进行广泛测试

🎮 工具设计至关重要！像对待人机界面一样，认真对待您的 Agent-计算机界面 (ACI)
✅ 三个核心原则：

• 保持简单
• 保持透明
• 设计清晰的工具文档

🎯 最终结论：成功不在于复杂性——而在于构建适合您需求的系统。从简单开始，进行衡量，然后仅在需要时进行扩展
